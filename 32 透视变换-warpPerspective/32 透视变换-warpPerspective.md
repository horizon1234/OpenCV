# 课程 32：透视变换——warpPerspective

> 适合人群：已经掌握仿射级别几何变换，准备理解“相机视角变化如何被投影模型描述”的学习者。

---

## 一、本课目标

本课要理解：

1. 为什么透视变换能把斜着拍的平面校正成正视图。
2. 仿射变换和透视变换的本质区别是什么。
3. 为什么 4 对点就足以确定平面到平面的单应映射。
4. 文档矫正、鸟瞰图和标定前处理为什么都常用 `warpPerspective`。

---

## 二、透视变换解决的是什么问题

现实世界里，同一个矩形平面从不同视角看上去并不总是矩形，它可能变成梯形或任意四边形。透视变换就是在描述：

“这个平面在一个视角下的投影，如何对应到另一个视角下的投影。”

所以透视变换不是任意三维纠正，它主要擅长处理同一平面上的映射关系。

---

## 三、它和仿射变换的区别

仿射变换能保持平行关系；透视变换一般不能。

这句话非常关键，因为它意味着：

- 如果只是平移、旋转、缩放、剪切，用仿射通常够用。
- 如果图像中的平行线因为视角原因汇聚了，就需要透视模型。

例如拍摄纸张、屏幕、棋盘、路面时，常见的“远处变窄”就是透视效应。

---

## 四、单应矩阵的直观理解

透视变换常写成 3x3 单应矩阵 $H$，它描述的是平面到平面的投影关系。

教学上不要求死记矩阵形式，但一定要理解：

1. 这是坐标映射关系，不是像素增强关系。
2. 变换后仍要做重采样，所以插值和边界问题依然存在。
3. 点选得不准，整张图都会歪。

---

## 五、为什么四对点就够

因为平面透视映射的自由度决定了，只要提供足够的对应点约束，就能求出唯一的单应关系。

在 OpenCV 里最常见的流程是：

1. 选取原图中的四个角点。
2. 指定目标平面上的四个理想位置。
3. 求矩阵。
4. 用 `warpPerspective` 做映射。

---

## 六、核心 API

```cpp
cv::Mat H = cv::getPerspectiveTransform(srcPts, dstPts);
cv::warpPerspective(src, dst, H, dsize);
```

重点不是把 API 背下来，而是理解：

- `srcPts` 决定你认为原图里哪些点属于同一平面。
- `dstPts` 决定你希望把这个平面展开成什么样。

---

## 七、典型失败案例

### 1. 矫正后图像歪斜严重

最常见原因是四点顺序错了，或者角点选取不准。

### 2. 结果看起来被拉伸变形

可能是目标输出尺寸设计不合理，目标平面纵横比和原物理比例不一致。

### 3. 本来不是同一平面的点硬拿来做透视校正

结果通常会出现局部对不上，因为透视变换只能正确描述同一平面内的映射。

## 九、课堂实验建议

### 实验一：文档四点矫正

1. 拍一张倾斜文档图。
2. 手动选四角点。
3. 矫正成正视图并比较边界拉直效果。

### 实验二：错误点序的影响

1. 故意交换目标点顺序。
2. 观察结果如何扭曲。
3. 建立“点顺序错误会毁掉整张图”的直觉。

### 实验三：非共面目标的失败案例

1. 选择存在明显深度起伏的场景。
2. 强行做透视变换。
3. 观察为什么只能局部对齐。

---

## 十、本课结论

1. 透视变换主要描述平面到平面的投影关系。
2. 它比仿射更强，但也更依赖正确的点对应。
3. `warpPerspective` 的价值在于把斜视平面重建为规范视图。
4. 真正学会这一课的标志，是你知道什么时候它能用，什么时候它本来就不该用。
